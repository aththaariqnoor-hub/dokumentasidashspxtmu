Tentang Aplikasi

Apa itu SPX Logistics Dashboard dan untuk apa digunakan

📦 SPX Logistics Dashboard

Sebuah aplikasi web yang dirancang khusus untuk membantu tim operasional SPX Tambang Ulang Hub dalam memantau dan mengelola data pengiriman paket setiap hari.

Sebelum ada aplikasi ini, data pengiriman dikelola secara manual menggunakan Google Apps Script yang terbatas. Sekarang semua informasi bisa dilihat dalam satu tampilan yang rapi, cepat, dan mudah dipahami.

🎯 Tujuan utama aplikasi ini: Memudahkan operator & fcaility lead dalam memantau performa kurir, melacak paket bermasalah (onhold, damage), dan membuat keputusan operasional berdasarkan data yang akurat.

👥 Siapa yang menggunakan?
Operator & Facility Lead SPX Tambang Ulang Hub yang bertugas memantau data pengiriman harian, performa kurir, dan menangani paket bermasalah.
🖥️ Cara akses?
Cukup buka browser (Chrome/Edge/Firefox) dan masuk ke alamat aplikasi. Tidak perlu install apapun. Bisa diakses dari komputer atau HP.
📊 Data dari mana?
Data diupload dari file CSV yang diunduh dari sistem SPX. Upload dilakukan oleh operator setiap hari atau saat dibutuhkan.
🔐 Keamanan?
Setiap aksi yang mengubah data (upload, hapus, edit catatan) dilindungi dengan password khusus yang hanya diketahui operator.

Dashboard — Rekapan Performa Harian
Halaman utama yang tampil pertama kali saat membuka aplikasi

Dashboard adalah pusat informasi utama. Di sini operator bisa melihat ringkasan semua paket dalam satu tanggal atau rentang waktu tertentu — berapa yang terkirim, berapa yang bermasalah, dan bagaimana performa tiap kurir.

✅ Delivered
Paket yang berhasil diantarkan ke penerima. Status: Delivered atau Selesai
🔁 Reschedule
Paket kembali ke hub, akan diantarkan ulang. Status: lmhub_received
↩️ Return
Paket dikembalikan ke pengirim. Status mengandung kata return
🔀 Misroute
Paket salah jalur atau status tidak dikenali (catch-all)
⚠️ Damage
Paket rusak, masih di station
🔴 Damage Return
Paket rusak, sudah keluar station

🚴 Tabel Performa Kurir

Menampilkan rekap per kurir: jumlah delivered, reschedule, return, misroute, damage, dan nilai CR%. Header kolom bisa diklik untuk mengurutkan dari terbesar ke terkecil (atau sebaliknya) — berguna untuk cepat melihat siapa kurir terbaik atau yang perlu perhatian.

💡 Cara baca CR% (Completion Rate): CR% = (Delivered + Return + Misroute) / Total × 100
≥ 95% Excellent   90–94% Warning   < 90% Critical

Monitoring Onhold — Lacak Paket Tertahan
Daftar paket onhold lengkap dengan validasi otomatis

Menampilkan semua paket yang berstatus onhold beserta informasi lengkapnya: siapa kurirnya, apa alasannya, sudah berapa kali onhold, dan apakah statusnya VALID atau TIDAK VALID berdasarkan aturan bisnis SPX.

📋 Aturan Validasi Onhold

✅ Akun STD / Standard
VALID jika alasan onhold adalah:
• recipient_reject
• recipient_reschedule
(berapa pun jumlah onhold)

TIDAK VALID jika alasan lain.
ℹ️ Akun Non-STD
recipient_reject + total ≥ 3 → ✅ Valid
recipient_reject + total < 3 → ❌ Tidak Valid
Bukan reject + total < 3 → ✅ Valid
Bukan reject + total ≥ 3 → ❌ Tidak Valid
🔗 Tombol Bukti Onhold: Setiap baris punya tombol yang langsung membuka halaman bukti onhold di sistem SPX — memudahkan verifikasi.
⚠️
Monitoring Damage — Kelola Paket Rusak
Pantau paket damage dan proses pengembaliannya

Menampilkan semua paket berstatus damage (masih di station) dan damage_return (sudah keluar station). Operator bisa mencatat status tindak lanjut setiap paket.

⚠️ Penting — Syarat Paket Muncul di Menu Ini: Paket hanya akan muncul di Monitoring Damage jika kolom Status di file CSV sudah diubah menjadi damage sebelum diupload.

Paket dengan status lmhub_received, lmhub_packed, return, atau status lainnya tidak akan muncul di menu ini, meskipun paket tersebut secara fisik rusak.

📋 Cara yang benar: Saat download CSV dari SPX, cari paket yang rusak, ganti nilai kolom Status-nya menjadi damage secara manual di Excel/spreadsheet, lalu baru upload file CSV tersebut ke aplikasi.

📝 Status Manual Paket Damage

Status Manual Artinya Efek ke Data
📋 Belum Dilaporkan Paket damage, belum ada laporan Status paket tetap damage
⏳ Menunggu Konfirmasi Sudah dilaporkan, menunggu keputusan Status paket tetap damage
✅ Selesai Dikembalikan Proses selesai, paket sudah keluar Status otomatis berubah ke damage_return ⚡
⚡ Otomatis! Saat operator memilih "Selesai Dikembalikan", sistem secara otomatis mengubah status paket di database menjadi damage_return — tidak perlu upload ulang CSV.
🏷️
Monitoring NS — Paket Akun NS
Filter khusus untuk akun yang mengandung kata "NS"

Menampilkan paket dari akun order yang mengandung kata "NS" pada nama akunnya. Fitur dan tampilan serupa dengan Monitoring Damage — bisa dicatat, difilter, dan ditelusuri per kurir atau tanggal.

Menu untuk membuat catatan operasional harian dengan format teks kaya (bisa tebal, miring, daftar, tabel, dll). Berguna untuk mendokumentasikan kejadian penting, kendala lapangan, atau pencapaian tim.

📝 Umum

⚠️ Kendala
Masalah atau hambatan yang terjadi
🏆 Achievement
Pencapaian atau prestasi tim
ℹ️ Info
Informasi penting yang perlu dicatat
🔐 Keamanan Catatan Harian: Menu ini dilindungi password yang hanya perlu dimasukkan sekali saat pertama membuka menu. Selanjutnya bisa tambah, edit, dan hapus catatan tanpa perlu input password lagi selama sesi browser aktif.
📂
Kelola Data — Upload & Riwayat Batch
Unggah data CSV dari SPX dan kelola riwayat upload

Semua data di aplikasi ini berasal dari file CSV yang diunduh dari sistem SPX. Menu Kelola Data adalah tempat untuk mengunggah file tersebut dan mengelola riwayatnya.

📤 Tipe Upload CSV

Tipe Isi File Kapan Diupload
📦 Forward Order Data pengiriman harian seluruh paket Setiap hari setelah data tersedia
⏸️ Onhold Data khusus paket yang statusnya onhold Setiap hari untuk update data onhold
🔄 Onhold Update Data terbaru untuk paket yang pernah onhold Saat ada update status paket onhold sebelumnya
♻️ Rollback / Batalkan Upload: Setiap upload tercatat sebagai "Batch" dengan ID unik. Jika ada upload yang salah, bisa dihapus dari tab Riwayat Batch — semua data dari batch tersebut akan dihapus dari database.
🔄 Header CSV Otomatis: Tidak perlu khawatir urutan kolom CSV — sistem membaca header secara otomatis dan mencocokkan ke kolom yang tepat di database, termasuk menangani typo umum di CSV SPX.

Aturan Bisnis

Logika perhitungan dan kategorisasi yang digunakan aplikasi

📊 Rumus CR% (Completion Rate)

CR% adalah angka yang menunjukkan seberapa baik performa pengiriman. Semakin tinggi semakin baik.

Jenis CR Rumus Keterangan
CR% Kurir Delivered ÷ Total × 100 Performa per kurir berdasarkan jumlah terkirim
CR% Account / General (Delivered + Return + Misroute) ÷ Total × 100 Paket yang "sudah selesai bergerak" dari hub
❓ Kenapa Return dan Misroute masuk hitungan CR? Karena paket tersebut sudah "keluar" dari hub dan bergerak — berbeda dengan Reschedule dan Damage yang masih "menggantung" di hub dan belum ada keputusan final.

Instalasi & Setup

Cara memasang dan menjalankan aplikasi

🖥️ Kebutuhan Sistem

Untuk Lokal (XAMPP)
• XAMPP (Apache + MySQL + PHP 8.0+)
• Browser modern (Chrome / Edge / Firefox)
• Windows / Linux / macOS
Untuk Hosting
• Shared hosting dengan PHP 8.0+
• MySQL database
• Akses phpMyAdmin untuk import SQL

📋 Langkah Instalasi

1. Siapkan database
Buka phpMyAdmin → Import file SQL secara berurutan:
schema.sql → schema_v2.sql → schema_v3.sql
2. Konfigurasi koneksi
Edit file config/database.php — isi host, nama database, username, password MySQL, dan ganti UPLOAD_PASSWORD dari default.
3. Set permission folder
Pastikan folder uploads/ bisa ditulis (permission 755 atau 775).
4. Akses aplikasi
Buka browser → masuk ke alamat hosting atau http://localhost/dashspx/ untuk lokal.
